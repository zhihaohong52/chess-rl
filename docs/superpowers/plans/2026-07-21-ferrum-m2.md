# ferrum M2 — Gen-0 NNUE Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace ferrum's hand-crafted eval (HCE) with a gen-0 NNUE trained on ChessBench, lifting anchored strength from the M1 result (2035 ± 38 CCRL) toward the ~2700–2900 M2 target.

**Architecture:** Standard perspective NNUE — 768 input features (piece-type × square × side-to-move perspective) → hidden accumulator → scalar output, quantized to int16/int8 for inference. Trained offline with `bullet` (Rust/CUDA) on a ThunderCompute A6000, integrated behind ferrum's existing `Eval` trait. Correctness-first (full-refresh eval) then speed (incremental accumulator + NEON SIMD). Every functional change is SPRT-gated at 8+0.08, concurrency 2, exactly as in M1.

**Tech Stack:** Rust (std-only engine + `bullet` trainer), Python (ChessBench→bullet data conversion), ThunderCompute A6000 (CUDA), fastchess + Ordo (gating, unchanged from M1).

**Design source:** `docs/superpowers/specs/2026-07-14-ferrum-nnue-engine-design.md` §5 (NNUE stack). **Ledger:** `ferrum/docs/ledger.md`. **Budget:** ~$20–25 approved, $0 spent through M1; M2 estimate ~$5–8 (data ~$1–2, training ~$4–6). Cloud spend begins in Task 3 and every cloud task is an explicit approval gate.

**Invariants preserved from M0/M1:** full-window negamax (no PVS/null-window in the PV/move loop; the NMP scout window is the one accepted exception); ray-scan sliders (no magic); `ferrum/**`-scoped CI stays green. NNUE is an eval swap behind the `Eval` trait — search is untouched except where the accumulator is threaded for incremental updates (Task 5).

## Task 5: Incremental accumulator + make/unmake hooks ($0, local, TDD)

Speed: maintain the accumulator incrementally so eval is O(changed features), not O(all pieces). The accumulator is search state.

**Files:**
- Modify: `ferrum/src/nnue.rs`, `ferrum/src/search.rs`, `ferrum/src/board.rs:184,238,275,288`

- [ ] **Step 1: Write the invariant test.** For a sequence of legal make/unmake moves from several FENs, assert the incrementally-updated accumulator equals a full refresh at every node:

```rust
#[test]
fn incremental_matches_full_refresh() {
    let net = Nnue::load("nnue/gen0.bin").unwrap();
    let mut b = Board::startpos();
    let mut acc = net.fresh_accumulator(&b);
    for mv in first_perft_line(&b, 4) {          // helper: a fixed legal line
        let u = b.make(mv);
        net.update_accumulator(&mut acc, &b, mv, &u);
        assert_eq!(acc, net.fresh_accumulator(&b), "incremental == refresh after {mv:?}");
        b.unmake(mv, u);
    }
}
```

- [ ] **Step 2: Run to verify it fails.** `cargo test --release incremental_matches_full_refresh` → FAIL.

- [ ] **Step 3: Implement incremental updates.** Add add/sub feature deltas to `Nnue`; thread an accumulator (or accumulator stack indexed by ply) through `negamax`, updating on `make`/`unmake` (and refresh on `make_null`/`unmake_null`, which don't move pieces). `eval` reads the current accumulator instead of full-refreshing. Keep the full-refresh path for the root and as the test oracle.

- [ ] **Step 4: Verify + bench.** All tests pass; `cargo bench`/`ferrum bench` node count unchanged (search identical), NPS up materially vs Task 4 full-refresh. Record NPS delta.
