# ferrum M3 — gen-1 king-bucketed NNUE Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace ferrum's plain-768 NNUE with a king-bucketed, 1024-hidden net trained on the full ~100M ChessBench corpus, to raise the engine from 2669 → ~2850–2950 CCRL.

**Architecture:** Extend the existing `Nnue`/`Accumulator`/`EvalKind` machinery (M2) to a versioned net format: v1 = plain 768 (gen-0, still loadable), v2 = king-bucketed mirrored 768×N. The feature index gains a per-perspective king bucket + horizontal mirror; the incremental accumulator (M2 Tasks 5–6) gains a **king-move refresh** — when a side's king changes bucket or crosses the mirror line, that one perspective is full-refreshed while the other stays incremental. All engine work + tests land locally ($0) with a *synthetic* bucketed net before any cloud training.

**Tech Stack:** Rust (std-only engine), `bullet` (pinned `cebc78a093d92cbc87e56cfef049184c225270b0`, CUDA) for training on a ThunderCompute A6000, `fastchess` + Ordo for SPRT/gauntlet, Python for the ChessBench→bullet converter.

**Reference spec:** `docs/superpowers/specs/2026-07-22-ferrum-m3-gen1-nnue-design.md`.

```rust
const NUM_BUCKETS: usize = 4;
const KING_BUCKETS: [usize; 64] = [ /* from bullet, Step 1 */ ];

impl Nnue {
    /// (bucket, mirror) for `perspective`, from that side's king square, matching
    /// bullet ChessBucketsMirrored exactly (verified in
    /// `bucketed_feature_index_matches_bullet_reference`).
    fn king_context(king_sq: u8, perspective: Color) -> (usize, bool) {
        let oriented = if perspective == Color::Black { king_sq ^ 56 } else { king_sq };
        let mirror = (oriented & 7) >= 4;                 // king on e-h files
        (KING_BUCKETS[oriented as usize], mirror)
    }

    fn feature_index_bucketed(perspective: Color, bucket: usize, mirror: bool,
                              color: Color, pt: usize, square: u8) -> usize {
        let is_enemy = (color != perspective) as usize;
        let mut view_sq = if perspective == Color::Black { square ^ 56 } else { square };
        if mirror { view_sq ^= 7; }
        bucket * 768 + is_enemy * 384 + 64 * pt + view_sq as usize
    }
}
```

    let mut acc: Vec<i32> = self.feature_bias.iter().map(|&b| b as i32).collect();

- [ ] **Step 3: Make `push_delta` king-context-aware**

Thread the **post-make** board into the pool update and refresh the perspective(s) whose king context changed. In `src/search.rs`, change `push_delta(&mut self, delta)` → `push_delta(&mut self, delta, board)` (board = state *after* `make`), and update its single caller in `make_move`. New body:

```rust
fn push_delta(&mut self, delta: &FeatureDelta, board: &Board) {
    if let EvalKind::Nnue { net, stack, top } = self {
        if *top + 1 == stack.len() { stack.push(stack[*top].clone()); }
        let (below, above) = stack.split_at_mut(*top + 1);
        let dst = &mut above[0];
        dst.copy_from(&below[*top]);
        net.apply_delta_bucketed(dst, delta, board, true);
        *top += 1;
    }
}
```

In `src/nnue.rs`, add `apply_delta_bucketed` that, per perspective, either full-refreshes (king context changed) or does the M2 incremental toggle. It compares the king context implied by the *pre-move* accumulator against the post-move board. Simplest correct rule: if the moving side's king moved at all, refresh that side's perspective from `board`; otherwise incremental. (Non-king moves never change either king context.)

```rust
pub fn apply_delta_bucketed(&self, acc: &mut Accumulator, delta: &FeatureDelta,
                            board: &Board, forward: bool) {
    if self.num_buckets == 1 { return self.apply_delta(acc, delta, forward); }
    // A king move is the only thing that can change a king context. Detect the
    // moving side from the delta (the KING piece appears in removed[0]/added[0]).
    let king_moved = delta.removed.iter().flatten()
        .chain(delta.added.iter().flatten())
        .find(|(_, pt, _)| *pt == KING)
        .map(|(c, _, _)| *c);
    for perspective in [Color::White, Color::Black] {
        if king_moved == Some(perspective) {
            // Bucket/mirror for this perspective may have changed → rebuild from board.
            acc.by_color[perspective.idx()] = self.accumulate(board, perspective);
        } else {
            let (bucket, mirror) = Nnue::king_context(board.king_sq(perspective), perspective);
            let (off, on) = if forward { (&delta.removed, &delta.added) }
                            else { (&delta.added, &delta.removed) };
            let a = &mut acc.by_color[perspective.idx()];
            for &(color, pt, sq) in off.iter().flatten() {
                self.toggle_feature(a, Nnue::feature_index_bucketed(perspective, bucket, mirror, color, pt, sq), false);
            }
            for &(color, pt, sq) in on.iter().flatten() {
                self.toggle_feature(a, Nnue::feature_index_bucketed(perspective, bucket, mirror, color, pt, sq), true);
            }
        }
    }
}
```

Note: for the non-moving perspective, its own king didn't move, so its `king_context` is unchanged by this move and equals what the parent accumulator used — indexing the ≤4 changed pieces with it is correct. Refreshing the moving perspective unconditionally on any king move (even within the same bucket) is always correct and simpler than diffing buckets; king moves are rare so the cost is negligible.

**Reverse-delta caveat:** the M2 test also checks `apply_delta(.., false)` restores the parent. With king-refresh, a reverse over a king move can't be reconstructed from the delta alone (the pre-move king context is gone). Since the *search* unmakes via a pool `pop` (not a reverse-delta — see `pop_delta`), drop the reverse-delta assertion from `check_incremental_matches_refresh` for king moves (guard it: only assert reverse restoration when `king_moved` is `None`).
